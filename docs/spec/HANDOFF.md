### 现状（2026-11-17 实测，逐条起进程跑）

```
总计 80 条：SKIP 80 · RED 0 · GREEN 0    （每条 rc=0，SKIP 都打印出来）
```

**这是如实状态，不是"接近完成"。** 79 条挂在 **T5**（扩展运行时本体），1 条挂在 **T1**（`EX-54`，机器编目从块 `vq0f03` 搬进应用层）。
`judge.sh` **v0 骨架已落地**（`scripts/judge.sh`）：`--list` 出 80 行 EX 编号，每条 case 只打一行 `SKIP: 等 T5（EX-nn）` 然后 `exit 0`，文件里 0 条真实断言（`grep -cE 'grep |cargo |curl |test -' scripts/judge.sh` = 0）。
三条 v0 自检全过：① `--list` 集合 == 附录 A 的 EX 编号集合（空 diff）；② 80 条逐条跑，全部 `rc=0` 且 stdout 以 `SKIP:` 开头、无空输出；③ 无判断逻辑。

**v0 顺手抓到的真事**：把 80 条判据各自的管道跑在 v0 桩上，有 5 条**当场变绿**（EX-13 / 27 / 38 / 51 靠 `wc -l`，输出恒为 1）—— 一个只会打印一行的桩就骗过了计数型判据。所以读法第 6 条新增："断言不许只有一个数，`| wc -l` = N 必须再配一条内容断言"。

### 进度是可数的

`./scripts/judge.sh --list | wc -l` = **80**（case 总数）；剩余量 = 逐条跑后仍打 `SKIP` 的条数：

```sh
./scripts/judge.sh --list | xargs -n1 ./scripts/judge.sh | grep -c '^SKIP:'
```

T5 每落一条判据，这个数减一。**SKIP 归零那天，扩展运行时才算做完** —— 不需要任何别的进度口径。

### 谁来填这 80 条

**T5 的小子**，不是 spec 线。spec 线到 `judge.sh` 的 **v0 骨架**为止，之后**不再碰任何代码**（包括 `judge.sh` 的内脏）。
v0 的边界写死在脚本头注释里：**每个 case 只打印一行 `SKIP` 然后 `exit 0`**，文件里不许出现任何一条真实断言 —— 骨架一旦长出判断，写 spec 的人就会为了让骨架"看起来更像完成"去改判据，那正是这条线一路在防的漂移。

**T1 → T2 → T3 / T4（可并行）→ T5**

| 票 | 内容 | 存活的判据 |
|---|---|---|
| **T1** | 搬迁 + 三层目录 + `docs/boundary-baseline.txt` 一次到位 | 内核 ch1 的 1/2/5/11/12、ch5 四条、ch6 三条、三层全部断言、`EX-54` |
| **T2** | `nous-ai` 拆 `types` / `providers` + 真相层去 providers 依赖 + 时钟注入 | S1/S2/S3 的判据、能力层三条 |

### 纪律（与内核 spec 同一套，不重复定义）

- 判据一律 `| tee` 输出命中行，不许 `grep -c`；无票号 = 删；每条判据单独起进程；路径先 `test -e`，缺载体 = `SKIP`（打印）。
- **SKIP 不是绿。** 本仓库已经四次被**工具**骗过，四次都是"跑出来绿、事实是红"：

| # | 工具怎么骗的人 | 结果 |
|---|---|---|
| 1 | 判据 6 的 grep 写的是 `std::process\|Command::new\|Child`，**漏了 `tokio::process`** | `nous-tools` 里 3 个真 spawn 一个都没命中，判据报绿 |
| 2 | 判据里写 `NousDesk/crates/core`，**那个路径不存在**（真名 `nous-engine`） | grep 空输出 = 绿 |
| 3 | `judge.sh` v0 桩每个 case 只 `echo` 一行 | EX-13/27/38/51 四条计数型判据**当场变绿**（`wc -l` 恒为 1） |
| 4 | 抽表器把单元格里的 `\|` **全局反转义** | 把 EX-57 的正则 `^\| (EX-[0-9]+) \|` 毁成选择分支，跑出 `GREEN: 1,22d0` |

四次教训同一条：**判据的敌人不是实现，是判据自己的形状。** 所以有了读法第 6 条（哨兵原则）和 `judgment-audit.md`（逐条审计哨兵）。
