# 判据哨兵审计 · 80 条

**规则**（读法第 6 条，本轮升级）：每条判据里必须有**一个只有真实实现才能产生的字节** —— 具体 `commit_seq` / entry id / 哈希前缀 / 错误文本 / `version` 数字，称**哨兵**。
形式 = **计数断言 + 内容断言 + 哨兵值**，缺一不合格。负向判据（"逐行空"）的哨兵换一种：**故意弄脏一次，它必须红**；红的那次就是哨兵。

**本文件只出清单，不动附录 A。签字后再改表。**

图例：`机` = 机械断言（命令里真跑）；`散` = 只写在逗号后面的散句里（**命令不验它**）；`—` = 没有。

## 形式问题的统一解法（61 条散句）

`judge.sh <case>` 的输出必须是**结构化一行**（如 `key=value` 若干段），判据改写成：

```sh
./scripts/judge.sh <case> | tee | grep -F 'commit_seq=5074'      # 哨兵
./scripts/judge.sh <case> | wc -l                                 # 计数（有计数时）
```

即：**哨兵进命令，不进散文。** 散文只配解释"为什么是这个值"。
