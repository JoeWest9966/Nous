# 票 2 · 左栏"移动"的十个方案（demo）

> 这一票**只做 demo**，不碰 `src/`、不碰 `server/`、不碰真模型。真模型是票 1，两边同时在跑。

## 要交付什么

一个新目录 `demo/sidebar-move/`，一格一格摆出**十个**左栏"移动"的交互方案，让人能在浏览器里真的点、真的拖、真的按键盘，然后挑一个。

照抄 `demo/button/` 的体裁（**先打开看一遍那个页面**）：

- `index.html` + `demo.css` + `main.js`，纯原生，**不 import 任何 React**，不碰 `src/` 里的一行代码
- 顶部：标题 + 一段 `lede` 说清这一页在比什么 + 一排 chip（`全部` / `01`…`10`，点一下只看那一格）
- 中间：`<main class="deck">` 里十张卡片，每张 = 编号 + 名字 + 一句"它想解决什么" + 一个可交互的左栏
- 底部：`看的时候重点看这几件事`（4 条，用可数的、能判对的句子，别写"体验流畅"这种）
- 浅色/深色切换、`prefers-reduced-motion` 下全部动画退化为瞬时

`vite.config.ts` 会扫 `demo/*/index.html` 自动当第二个入口，**不用注册**。构建完的地址是：

```
http://100.106.43.81:4790/demo/sidebar-move/index.html
```

（本机 `http://127.0.0.1:4790/demo/sidebar-move/index.html`）

## 假数据：十个方案共用同一棵树

不许各写各的。同构的一棵三层树，让"移到别的组"和"同级排序"都能看出来：

```
N
├── src              组
│   ├── App.tsx      块
│   ├── utils.ts     块
│   └── tokens       组
│       └── theme.ts 块
├── docs             组
│   ├── ADR          组
│   └── notes.md     块
└── server.ts        块
```

十个方案里，`id` 都是 `n1`、`n2`…这种短号（demo 里不需要六位乱码），但**必须遵守**：移动只换位置，id 一个字符都不变。

## 十个方案

每个都必须回答同一个问题：**"我要把 `App.tsx` 挪到 `docs/ADR` 前面"怎么用你最少的动作做到。**

| # | 名字 | 怎么动 | 它想证明什么 |
|---|---|---|---|
| 01 | **拎起来** | 行尾一个"移动"钮 → 该行变灰、顶部浮出胶囊"正在移动 App.tsx · Esc 取消"→ 左栏其余行全变落点：**点组 = 放进该组末尾，点块 = 插到这块前面** | 基线。一个状态、一种点击，靠目标类型自己区分"换爹"和"排序"，不需要第二套 UI |
| 02 | **目标优先** | 先点"移到…"，左栏切成"只列组"的清单，点一个就落子 | 动作更少，但**排不了序** —— 摆在 01 旁边，让人看清省下的那步代价是什么 |
| 03 | **拖 · 三段** | 真拖拽。落点分上/中/下三段：上=排它前面，中=进这个组，下=排它后面，带插入线 | 拖拽的上限。三段热区能不能解释清楚，是这一格唯一的问题 |
| 04 | **拖 · 一段** | 拖到**组**上 = 进组；拖到**块**上 = 排在它前面。不做三段 | 同样的拖拽，砍掉热区解释成本。和 03 对比才知道三段值不值 |
| 05 | **幽灵行** | 拎起来后，待移动节点变成一条跟随光标的半透明幽灵，原位置留一道空槽；松手落到光标所指的行 | 单手握鼠标、不用精确瞄准。代价是"落点在哪一行"要靠光标位置猜 |
| 06 | **两栏** | 左栏选源 → 右栏弹出目标树（可搜、层级压平）→ 点一个组/行 | 树很深的时候，一屏塞不下两层选择 |
| 07 | **命令面板** | `⌘K` 里先选源再选目标，全键盘，路径补全（`docs/ADR` 打 `dadr` 也能命中） | 键盘党的上限。鼠标党不会用，但每次用它都是三步 |
| 08 | **改地址** | 选中节点，左栏顶部露出它那条 `tree` 路径，**直接编辑这段路径**再回车 | 把"位置"当字符串改。爽和危险成同一件事：手一抖就进错组 |
| 09 | **键盘游标** | 拎起来后 `↑`/`↓` 走行，`→` 进组、`←` 出组，`Enter` 落 | 纯键盘、不弹任何新 UI。要求左栏永远显示全树、不折叠 |
| 10 | **改爹下拉** | 行内嵌一枚下拉，列出所有组（当前爹打勾），选一个 = 换到这个组的末尾 | 最朴素、最不可能点错。它也在提醒：**"排序"是个独立需求**，这个方案里做不了 |

01 和 09 是同一件事的两个极端，02 和 06 也是，03 和 04 也是 —— **摆在一起是为了让人做减法，不是为了让人选最多的那个。**

## 每张卡片的下限

- 真的能操作：点/拖/按键之后，左栏的树要**真的变成移动后的样子**（demo 自己的 `children` 数组，摘出来再插进去，十几行就够，别引模型）
- 落子后 id 不变 —— 让每行左边一直显示着 `id`，移动完自己盯着看
- `Esc` 中途取消，树回到原样
- 鼠标能到的每个动作，键盘也能到（`Tab` + `Enter`，或 09 那种方向键）
- 只动 `transform` / `opacity` / 颜色；不要动 `width` / `height` / `top` 做动画（让位用 `translate` 或用 `grid-template-rows` 一格一格跳，别逐帧动画布局）
- 手指够不着的密度就别做：这是桌面左栏，不是手机

## 不许做的事

- 不碰 `src/`、`server/`、`docs/tickets/01-move-model.md`（那张票有人同时在改）
- 不加任何依赖（`package.json` 一行不改）
- 不写 ADR、不写设计文档 —— 这一票的产出就是那十个能点的格子
- 不实现"真功能"：这一页不需要落盘、不需要撤销栈、不需要接 API。**它是选题板，不是产品**

## 这台机器上两张票同时在跑

所以规矩：

- **`npm run build` 和 `systemctl restart nous-panel` 归你**（票 1 只用 `tsc`，不构建、不重启）。构建前先 `git status` 看一眼有没有别人的半成品被卷进 `dist/` —— 不会，`dist/` 在 gitignore 里，放心。
- 提交时**点名路径**，绝不用 `git add -A`：
  ```bash
  git add demo/sidebar-move demo/demo链接.md
  ```
- push 前先 `git pull --rebase`。
- 提交信息用中文，说清每个方案赌的是什么；有实测（比如 03 的三段热区在 28px 行高下有多难打中）就写数字。
