块 / 组 · 唯一 id —— 十二个方案

同一棵树，同一串操作，十二种给节点起 id 的办法。每一格里是这个 id 现在长什么样；按下面的按钮压它，看谁的 id 还认得出人。

没动 变了 —— 老 id 已经找不到这一块 指错人 —— 老 id 现在指向另一块

每格会告诉你认不认得

只有三条判据

  1. 稳定 —— 改完结构（插、删、改名、搬家、重开），同一个 id 还能找回同一块吗？变了是麻烦，指错人是灾难：它不报错，它静静地让你改了另一块。
  2. 套娃 —— 从 id 能不能看出谁是谁的爹？能的话 startsWith 一行代码就等于「我这一整支」，整支复制 / 整支统计 / 整支删除都白送。
  3. 可念 —— 人能不能在群里把这个 id 打出来、在电话里念出来。

压力测试在测什么

  • 插一块 —— 序号派（1.2.1）会把后面所有兄弟重新编号，而且新号正是旧号。
  • 删中间 —— 同上，位置派集体前移，名字派无动于衷。
  • 改组名 —— 名字派一整支全换号；随机派一个都不动。
  • 搬走一支 —— 含地址的方案整支变号（地址变了，本来就该变，代价是所有旧引用一起废）；只带自己名字的（名字@段、双标识）纹丝不动 —— 它是稳的，但它从此不再告诉你这块在哪。
  • 重开 —— 模拟刷新：计数器归零，第 1 块又变成 n1，而上辈子的 n1 是另一块。严格说重开是一盘新棋，这里只测一件事：把 A 盘的 id 贴到 B 盘上，会不会安静地打开另一块。

结论

没有一张卡全绿，这不是我偷懒 —— id 只有两个字段可用：身份和地址。要关系就得把地址编进去， 要稳就不能让地址参与身份。十二个方案全都在这个取舍上选了一边，除了最后一个：

顺带一提，压到「重开」那一步会发现一件反直觉的事：指错人的不止序号派 —— 名字路径、序号路径、内容 hash 一样会。因为它们的 id 是确定性的：两盘结构一样的棋会算出同一串 id，于是 A 盘的链接在 B 盘上安静地打开另一块。 而随机派、段路径、名字@段、双标识全身而退 —— 它们跟「第几个」「叫什么」都没关系。

段路径（每段是那个节点自己的不可变短 id，父子靠前缀相连）是唯一一个两边都占一点的 —— 关系真的在 id 里，而每一段永不改变。它的代价是长，和「搬家就换地址」。

我的落地建议是三个字段各管一件事：segPath 给人看和寻址　+　 一条不可见的 uid 兜底（搬家、误删后还能找回原对象）　+　 name 只做显示（随便改，不进 id）。
