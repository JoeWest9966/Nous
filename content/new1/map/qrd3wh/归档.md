# 归档功能实现记录（qrd3wh）

方案见 `/opt/Nous/docs/adr/0001-session-archive-copy-and-purge.md`。
这一页记实现细节和留给下一手的话。

## 端点（全在 qrd3wh 引擎上）

| 端点 | 干什么 | 前置（不满足回 409/400/404） |
|---|---|---|
| `POST /v1/sessions/:id/archive` | 复印死子树进 `data/archives/gen-YYYYMMDD.sqlite` + 写墓碑 | 忙拒；有活分支拒（列出 children） |
| `POST /v1/sessions/:id/purge` | 撕原件：一个事务 DELETE 九张表 + 墓碑记 purged | 忙拒；没归档过拒；已撕过拒；复印件不完整拒（双向校验） |
| `POST /v1/archive/:id/restore` | 打捞：原样 INSERT 回活库 + 抹墓碑，body 带 `{"gen":"YYYYMMDD"}` | 已在活库拒（重复打捞） |
| `GET /v1/archive` | 浏览归档库：`{gens:[{gen, items:[…]}]}`，每条带 name/archived 墓碑/live | — |
| `GET /v1/sessions` | 默认藏归档；`?archived=1` 给全量（每节点带 `archived` 墓碑字段） | — |

## 文件

- `archive.js`（块里）：复印/撕/捞/浏览四台机器 + `openArchive({ dataDir, liveDbPath, log })`。
  **不 import server.js**（顶层 await），自成一个能单验的模块。
- `test/archive.test.mjs`：临时 durable 库上跑全生命周期，8 组断言（`node test/archive.test.mjs`）。
- `server.js`：`Sessions` 文档加 `archived` 段（老盘没这个键，`setArchived` 里 `??=` 接住）
  + `setArchived`/`archivedMarks` + `tree()` 每节点带 `archived` 字段 + 四条路由。

## 埋过的坑（踩过的都在代码注释里）

1. `record_ids` 的闭包查询：会话 id 和文档 id 两拨合起来查，占位符按总长重算 ——
   复用会话的占位符就是 `column index out of range`。
2. gen 文件第一次是空文件：`initGenSchema` 铺九张表，**照抄活库的 STRICT + CHECK**，
   列约束不一样的话行搬回来就过不了活库的检查。
3. 同一天二次归档 = 同一个 gen 里已有旧行：先清那棵子树的旧复印再插（新复印一定包含
   闭包全部行，留下的旧行只会是过期副本）。
4. 完整性是**双向**的：打捞后聊了新 entry 再撕，新 entry 不在复印件里 —— 拒撕，
   重新归档才行。这个约束测试里差点当 bug 删掉。
5. **purge 后墓碑在 `?archived=1` 里看不到**（行删了 `tree()` 没有这条会话）——
   已补：`GET /v1/archive` 现在把 Sessions 里的墓碑和名字合进浏览结果，
   每条多三个字段：`name`、`archived`（`{at,gen,purged}`）、`live`（活库还有没有原件）。
   页面拿这两个字段推出四态（原件在 / 已销毁 / 已捞回 / 无墓碑）。

## mcfpqm（storage-Archive）页面

已建：`content/new1/map/mcfpqm/index.html` + `AGENTS.md`。纯静态页，只走 HTTP。
按 gen 分天分组、组内按 fork 关系画树（复用 pxbgng 的缩进/引导线几何），
行尾 hover 出两种操作：「撕原件」（原件在时）和「打捞」（已销毁/无墓碑时）。
轮询 5 秒且页面隐藏时不问。

页面**不在这一页再判一遍硬条件** —— 忙、活分支、复印件完整性都只由 qrd3wh 拦（409），
页面只显示错误原文。两处规则一定会分叉。

## 真删 ≠ 文件变小

DELETE 只把页标成空闲，`agent.sqlite` 字节数不变。真缩要 VACUUM，挑静默时刻或
重启间隙做（`PRAGMA freelist_count` 可以先看看有多少页能回收）。现在 946KB，
不急。
