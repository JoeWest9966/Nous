# jtjzw5 · Ultimate-Template —— 终极模板那一段的页

`Nous-Template` 仓里 `Ultimate-Template/` 这一段的视图。**只发静态文件**：数据全是浏览器去问
`qrd3wh` 的 `GET /v1/presets/Ultimate-Template`，这一块不读仓库、不跑 git、没有 `data/`。

跟 `3699b9`（同一仓的另一段 `Session-Template`）是同一套骨架、不同的段。两页不互相窜：
段名各写各的（`public/api.js` 的 `SECTION`），改这一段碰不到那一段。

## 一条 = 触发器 + 触发器的参数 + 一条会话模板

`ultimate.json` 的形状定下来了（`sections.json` 里那一段的 `checker` 是 `ultimate`）：

```json
{ "v": 1, "name": "…", "summary": "…", "category": ["…"],
  "trigger": "single-shot", "params": { "epoch": 1800000060 },
  "session": "weekly-report", "enabled": true }
```

**触发器只回答「什么时候起」，会话模板回答「起什么」** —— 两个引用，一个都不能少。

## 参数表单是**照触发器的声明画出来的** —— 页面不认识任何触发器的名字

这一页里**不许**出现 `if (触发器名 === "single-shot")` 这种代码。

- 触发器在 `Nous-Trigger` 仓里自己声明要什么参数（`nous.json` 的 `params`）。
- 引擎把那份声明原样带给页面（`GET /v1/triggers`）。
- 页面**只看参数类型**决定画什么控件：`epoch` → 日期时间、`number` → 数字、
  `string` / `text` → 文本、`boolean` → 开关、`select` → 下拉。

所以**新加一个触发器 = 它自己声明参数，这一页一个字节都不用改**。
要加的是**类型**（封闭词汇表：`epoch / number / string / text / boolean / select`），
不是给某个触发器开后门 —— 那会让两份代码迟早对不上。

`epoch` 在盘上是 **UTC 秒**，页面上人挑的是**本地时间**：输入框用 `datetime-local`，
存取各转一次（`epochToLocalInput` / `localInputToEpoch`）。控件旁边那句「存进去是 UTC 秒」
是故意留的 —— 不说清楚，人会以为存的是本地时间戳。

## 引用在不在，**引擎说了算**

这一页不判断「触发器还在吗」「这条会话模板还在吗」：它判断不了（那些名单在引擎那儿）。
引擎给 `resolved`，这一页只翻译。**红卡上写清是哪一条不在了** —— 只写「引用失效」等于
让人自己去数。

参数漂移（触发器改了参数名，这条还留着旧的）算**引用失效**的另一种长相，归同一档：
卡片红着，详情里那一条标「触发器里没这个参数了」。

## 空着就是空着 —— 这里**没有示例数据**

「先塞几条假数据看看皮」这件事做过一次，删掉了。理由：**填满的假页面会被当成真页面** ——
人会以为仓里有五条，然后去找为什么启动不了。空页面加一句实话，比好看的假数据诚实得多。

空状态要说清三件事：这一档为什么空（整段空 / 筛出来空）、东西应该从哪儿来、现在缺什么。
`emptyHint()` 就管这三句。

## 卡状态：`failed > invalid > unpublished > ok`

顺序就是「先修哪儿」：

| 状态 | 长相 | 意思 | 修哪儿 |
|---|---|---|---|
| `failed` | 红边实线 + `specError` 一行 | 这条自己写坏了 | 这里 |
| `invalid` | 红边 + 点名哪条引用不在 | 引用的东西没了 | **那边** |
| `unpublished` | 琥珀虚线 | 盘上有、HEAD 没有 | 点发布 |
| `ok` | 实边 | 好的 | — |

`failed` 压在 `invalid` 上面是有理由的：写坏了的那条**连解析都做不了**，这时报「引用失效」
是骗人 —— 引用可能全是好的。

## chip 的三态

| chip | 长相 |
|---|---|
| 触发器 | `触发器 <名>` / 红（不在）/ `触发器 未选` |
| 参数 | `参数 N 个`（悬停列出每个参数的值）/ `参数 无` |
| 会话 | `会话 <名>` / 红（不在）/ `会话 未选` |
| 开关 | 一个能点的 chip：`开着 · 点停` / `已停 · 点开` —— 点了就写回 `ultimate.json` 的 `enabled` |

「什么时候起」和「起什么」是**两件事**，所以是两个 chip —— 合成一个就说不清了。

## 开关与试跑（两个动作，别混）

卡片 footer 上是两个**不同**的动作：

| 按钮 | 打哪 | 干什么 |
|---|---|---|
| ▶ 直接起会话 | `POST /v1/presets/launch` | **跳过触发器**，立刻起一条会话 —— 测参数 / 会话模板 / 展开 |
| 问触发器 | `POST /v1/combos/:name/fire` | **真问一次触发器**：它说 fire 才起会话 —— 和调度器同一个判断 |

「跑不出来」时两条给的答案是两回事：前者问「这条组合能不能跑」，后者问「触发器现在认不认」。
所以别把两个按钮合成一个。

开关是**引擎写的**（`/v1/combos/:name/enable|disable` → 组合自己的 `ultimate.json`），
这一页乐观更新、失败回滚；本地不留第二份「开着没开」。

顶栏那行「调度器 上一拍 HH:MM:SS」来自 `GET /v1/combos` 的 `scheduler`：开关改完要等下一拍，
这行是唯一能解释「为什么它还没跑」的东西。

## 文件

```
package.json        type: module + scripts.start（宿主凭这一条起进程）
server.js           纯静态（剥 NOUS_SELF、403 目录穿越、no-store），默认 PORT=4787
public/index.html   顶栏 / 黄条 / 左栏 / 筛选 / 网格 / 详情浮层
public/model.js     纯计算：卡状态 / chip / facet 树 / 筛选 / 叠放顺序（一个 DOM 都不碰）
public/api.js       ctx 解析、段名补齐、错误信封（503 → SectionNotReady）
public/app.js       DOM 那一半：渲染、详情、抽屉、Esc
test/               model.js / api.js 的测试（不测 DOM）
```

## 不做的事

- **不写 `data/`。** 真相只有 `Nous-Template` 仓。
- **不跑 git。** 发布 / 归档全走 `qrd3wh`。
- **不复刻引擎的判定。** 名字规则、引用存在性、条数上限 —— 一处（`qrd3wh/presets.js`）。
  这一页只翻译结果，服务端那一行错误原样显示。
- **不在窄屏藏掉类别。** 左栏在手机上是个抽屉，所以工具栏上必须有那个能拉开它的按钮。
- **不塞假数据。** 段没装好就画成空的 —— 空页面 + 一句实话，比好看的假数据诚实。
- **不认触发器的名字。** 见上面「参数表单是照触发器的声明画出来的」。
- **不判断引用在不在。** 那是引擎的判定；这一页翻译结果，不自己算。
- **不维护第二份开关。** 开着没开只有 `ultimate.json` 的 `enabled` 一处，页面只翻 UI、失败回滚。
