# extend（vbe4pt）· Nous 自研扩展的清单前端

一页视图：**`Nous-extend` 仓库里有什么** + **正在跑的 qrd3wh 进程里装着什么**，
外加两件写回仓库的事：**类别**（8 秒 debounce 自动推）和**源码**（保存立刻、发布显式），
一件只在这台生效的事：**删除本地 / 安装回来**，以及一件可恢复的仓库操作：**归档 / 恢复 / 彻底删除**。
以前是 pi CLI 扩展的管理器（对账 / 收编 / 装卸 / 快照 / 出厂检查），那套跟 pi-durable 无关，
2026-11 整条退场。代码在 git 历史里，运行时存档在 `data/legacy-pi/`（没有代码再读它）。

## 为什么只剩发静态文件

数据不走这个进程。页面自己去问 qrd3wh 的 `GET /v1/extensions`，地址从宿主的
`__nous/ctx` 里找 `qrd3wh` 那个块拿。所以 `server.js` 现在只做一件事：把 `public/` 发出去。

块之间只走 HTTP，地址只从宿主的 ctx 来 —— 这一块里一个 `/p/…` 都不拼。

## 两套扩展，别混（这一页只管下面那套）

| | pi CLI 扩展 | Nous 扩展 |
|---|---|---|
| 形态 | 磁盘上的 `.ts` 文件 | 进程内对象 `{name, tools?, sections?, hooks?, wraps?}` |
| 真相在哪 | 安装位（`~/.pi/agent/extensions/` 等） | `registry.install()` 之后的内存 |
| 启停 | 改名 `x.ts` ↔ `x.disabled.ts` + `/reload` | 一次 `install()`，同名就地替换，不重启 |
| 版本 | 文件时间戳 | git commit（`extensions.lock.json` 钉着） |

给下面那套套「改名 / reload」的开关会得到能点但不起作用的东西 —— 所以这一页**不给按钮**。

`nous` / `skills` 两个是启动路径上硬编码 import 的核心扩展，永远不许删（按钮灰着）。
其余扩展按 `index.json` 逐条 `import` 装载：一个写坏了只跳过它，不拖引擎下水。

## 页面上每一栏在说什么

版式照 68kazk 那个编目面板：**左栏类别 facet + 主区商品卡网格**，一个扩展 = 一张商品卡。

- **lock / HEAD**（右上）：`extensions.lock.json` 钉的提交 vs 仓库 HEAD。不一致就是红的 ——
  这是「改了仓库但没重启，跑的还是旧代码」唯一能看见的信号。
- **左栏类别**：缩进的类别树，每个类别（带计数）+ 底部「+ 新建类别」。点一下筛选，**父级筛出整枝**
  （点「工具」连「工具/搜索」一起出来；结果区会显示「工具 · 含 N 个子级」）。每行右侧有可见的 `⋯`
  菜单：新建子类别、编辑类别名称、删除类别（右键 / 长按只是快捷方式）。左栏不放常驻说明文字。
- **商品卡**：只放身份 —— 字母砖（颜色由名字 hash，永远同一个色） + 名称/版本 + 说明 +
  提示词段 / 依赖 / 在用 三个数 + 右上角常驻的 `⋯`。
  **未装入**= 红角标 + 虚线红边（菜谱上有、厨房里没有），**默认**= 绿角标（新会话默认选），
  **装载失败**= 实心红角标 + 实心红边 + 卡上一行错误摘要（代码坏了，进程里还是旧版本），
  **未发布**= 琥珀虚线边 + 琥珀角标（磁盘上有、HEAD 里没有，别人 pull 不到），
  **仅在仓库**= 固定灰卡 + 虚线灰边（本地卸载了，仓库里还在），统一沉到列表最后。
  类别 chip、变体行、卸载/归档按钮**都不在卡上**：点卡进详情，右键（长按 / `⋯`）出菜单。
- **顶部筛选栏**：全部 / 内置类别 / 未分类 / 状态 / 已归档。状态那组是 已装 / 未装入 / 仅仓库 /
  未发布 / 装载失败，**非零才出现**；色点只是辅助，文字才是本体。图例就是筛选，不另写说明。
- **「已归档」**：只在 `.archive/` 非空时出现，点开就是回收站：一行一个已归档的扩展，
  `恢复` / `彻底删除`。
- **「＋ 新建扩展」**：在结果计数旁边，见下面「新建扩展」一节。
- **右上角同步 chip**：已同步 / 待同步 N / 推送中 / 失败 / 拉取失败 / **本地已删 N 个扩展** /
  **N 个扩展装载失败** / **N 个扩展未发布**。最后两个都不是同步欠账：
  装载失败是代码没生效，未发布是本地有、仓库没有。

> pi-durable 自带的（`coding-tools`）和技能名牌（`skill:<名>`）**不再列出来**：
> 它们不进 `catalog`，也不该有类别/装卸按钮。谁写的代码谁进账。

## 详情：点卡进来（主区换页，不是浮层）

电商那套：列表 → 商品详情。详情占的是**主区** —— 左栏和筛选条不动，网格让位。
不是又一个右侧浮层：右边那条边已经归代码抽屉了，两个浮层抢同一条边迟早互相踩。

里面四块：**类别 / 变体 / 清单（文件·提示词·依赖·在用）/ 仓库（发没发布·装没装）**，
顶上色砖 + 名字 + 版本 + 状态角标 + 说明 + `代码 ›`。

分工定死：

| | 在哪 | 为什么 |
|---|---|---|
| 类别勾选 | **只在详情** | 一份 `category[]` 开两个写入路径必然漂移（同「不做元数据表单」那条）|
| 变体行 | 详情 | 点行还是原来那个弹层，`+` 还是原来那个新建 |
| 代码 / 卸载 / 归档 / 装回 / 重试装载 | **卡片菜单** | 菜单只管动作，不进编辑 |

`Esc` / 左上 `‹ 返回` 回列表。**换筛选、打字搜、进归档区都等于回列表** —— 详情开着
再切筛选，会出现「筛选结果藏在详情背后」的假象。

## 卡片菜单：右键 / 长按 520ms / `⋯`

跟左栏类别行**同一套菜单件**（`mountMenu`：视口内夹紧、点外面 / `Esc` / 滚动 / 改窗口大小都关），
同一套手势（`attachMenuGesture`：长按 520ms、挪动超过 10px 当滚动、松手吞掉那个 `click`）。
两套各自算位置的代码必然一套对一套错。

```
查看详情  ‹类别 · 变体›
看代码    ‹读 / 改›          ← 灰卡上禁用（源码不在工作区里）
重试装载  ‹立刻重来›          ← 只有装载失败时出现
─────
类别      ‹在详情里勾›        ← 只是跳过去 + 打开输入框，菜单不做第二个编辑面
─────
卸载本机  ‹仓库不动›          ← 核心扩展禁用
归档/删掉 ‹可从归档恢复 / 没有历史可找› ← 核心扩展禁用，红色
```

排序是「读 → 写 → 销毁」，写和销毁之间一定有分隔线。
灰卡只有一项 `装回本机`，其余全不出现（没文件可看、没什么可卸）。

三个看不见的入口规矩：

- **`⋯` 是可见的那一个。** 右键 / 长按只是快捷方式 —— 只藏右键里，第一次进来的人
  永远找不到代码和卸载。
- **键盘**：卡片 `Enter` / `Space` 进详情，`ContextMenu` / `Shift+F10` 开菜单。
- **`Esc` 的层级**：菜单 → 变体/新建弹层 → 代码抽屉 → 详情 → 列表。菜单排最前，
  因为它是最后一次交互；不这么排的话，Esc 关菜单会顺手把背后的详情也关了。

## 类别（写回仓库，8 秒 debounce）

类别**不在这一页存**。真相在仓库里，两份，取并集：

| 文件 | 是什么 |
|---|---|
| `<ext>/nous.json` 的 `category: string[]` | 哪些类别挂在这个扩展上 |
| `<EXTEND>/categories.json` 的 `categories: string[]` | 仓库认得哪些类别（**词表**）|

词表存在的理由只有一个：**一个刚建、还没挂到任何扩展上的类别，不能建了看不见**。
（这是照着 68kazk 的「词表 ∪ 记录」来的。）

### 子类别：路径就是结构

类别是**路径**，`/` 是分隔符：`工具/搜索` 是 `工具` 底下的 `搜索`。父子关系不存 ——
没有 `parent`、没有 `children`、没有 `{name, children}` 的树文件。跟 Nous 的 `tree` 一样：
**路径是算出来的，不落盘。**

```
"category": ["工具", "工具/搜索"]
"categories.json": { "categories": ["工具", "工具/搜索", "工具/爬虫"] }
```

四条不变量：

1. **祖先自动进词表。** 打上 `工具/搜索`，`工具` 这个节点就必须存在（`writeCategories` 补）。
2. **祖先不写进扩展的 `category`。** 一个扩展属于 `工具` 是因为它的标签前缀是 `工具/`，
   不是因为它多存了一条。想让它"直接"是 `工具`，就真去勾 `工具`。
3. **计数含后代、按扩展去重。** 父级计数 = 挂着它或它任何后代的扩展数；一个扩展同时挂父子只算一次。
4. **`/` 是保留符。** 段会自动 trim、空段丢弃（`a//b` → `a/b`）；控制字符和超过 40 字的段 400。

**改名 = 整枝改前缀，所以也是移动。** `工具` → `工具箱` 带着 `工具/搜索` 一起走；
`搜索` → `工具/搜索` 就是把它（连同自己的子树）挪进 `工具`。目标前缀下已有任何类别返回 **409，
不自动合并**；改到自己子树里（`A` → `A/x`）400。

**删除 = 删整枝。** 删 `工具` 会连 `工具/搜索`、`工具/爬虫` 一起从词表和所有 `nous.json` 摘掉。
确认框写明「连同 N 个子类别」。

前端只做派生：拿扁平的路径表，自己建树、算缩进、算计数。所以服务端返回的永远是
`categories: string[]`，没有一个树结构要两边对账。

### 内置类别

`Basics` 是内置的（`qrd3wh/server.js` 里的 `PROTECTED_CATEGORIES`）：像「全部」一样永远在，
**删不掉、改不了名**——改名等于绕开删除锁，所以一起禁。

- 词表被人清空也丢不了：`readCategories` / `writeCategories` 都会把内置类别补回去。
- 请求返回 `protected: ["Basics"]`，前端照这份名单决定菜单里给不给「编辑/删除」——
  **名单只有一份，不在前端再抄。**
- 删 / 改名内置类别（或它的祖先）→ **403**。
- 往里挂扩展、建子类别照常；**子类别本身不是内置的**，照常删改。

```
POST <qrd3wh>/v1/extensions/category    {name, category[]}
  → 写 <EXTEND>/<name>/nous.json，跑 index.mjs 重扫 index.json
  → 新出现的标签自动进 categories.json 词表；校验失败原样回滚

POST <qrd3wh>/v1/extensions/categories  {op:"add",    name}          ← 新建空类别（name 可以是路径）
POST <qrd3wh>/v1/extensions/categories  {op:"rename", name, to}      ← 整枝改名 / 移动
POST <qrd3wh>/v1/extensions/categories  {op:"remove", name}          ← 删整枝（词表 + 所有 nous.json）
GET  <qrd3wh>/v1/extensions/categories                               ← {categories[], protected[]}

GET  <qrd3wh>/v1/extensions/sync        → {head, dirty, ahead, behind}
POST <qrd3wh>/v1/extensions/sync        → commit + push 回 GitHub
```

**为什么写盘走 qrd3wh 不走这里：** Nous 铁律，块之间只走 HTTP、不读别人的文件夹。
`/opt/Nous-extend` 是 qrd3wh 的地盘，它握路径和 git；这一块（vbe4pt）仍然没有后端状态。

**同步节奏：写盘立刻，commit+push 攒 8 秒。** 选盘时不断勾标签，仓库不该长出五条碎 commit；
页面关掉 / 切后台前会强制 flush。

**失败必须红。** `git push` 挂了（没凭据、远端动了）就显示出来并允许点它重试；
绝不装成功——本地改了、远端没动、页面写「已同步」是最坏的那种假象。

**改名的半径是整枝。** 改的是词表 + 每个挂着旧前缀的 `nous.json`（先快照，`index.mjs` 不认就整体回滚）。

## 复制成新扩展

卡片「⋯」菜单里的「复制成新扩展」：起个新名字 → 拷一份目录 → 落盘就完事。**历史不带**，
旧提交还在原扩展里（`git log --follow` 都还在）。

为什么这东西比看上去危险一倍：**名字是写死在入口里的**（`defineExtension({ name: "123" })`）。
`cp -r` 一个 456 出来而不改那行，下次 reload 两个扩展注册同一个名字，**新的把原来的顶掉**，
而页面上两张卡都好好的 —— 这种失败没人能自己诊断。所以：

- 改名交给后端做，**只认 `name: "旧名"` / `"name": "旧名"` 这种字符串字面量**，不做全文替换；
- 入口里找不到这个字面量 → **整个副本删掉、报错**，绝不造一个会撞名的目录；
- 改完立刻过 `node --check`，再让 `index.mjs` 认一遍（不认也删）；
- 结果里带 `rewritten[]`，前端在 toast 里明说「名字改了，抽屉里能看 diff」。

清单只动 `name` / `summary` / `category`，`file` / `entry` / `sections` / `needs` / `version`
原样 —— 代码没变，段落和依赖就没变。谁要是顺手把 `sections` 重置成 `[]`，复制出来的扩展
立刻「清单对不上」。

落盘是**未发布**：复制不等于发布，提交/推送仍然走未同步弹窗或抽屉的「发布」。造完顺手
reload 一次（和「新建扩展」一致），装不上会在卡片上标红并给重试。

⚠️ 两个已知坑（都踩过，各留了一条清理提交）：

1. **`index.json` 会变脏**，而它属于「类别词表」那一档 —— 类别那条 8 秒 debounce 是自动提交的。
   现在后端提交前会把「HEAD 里没有这个目录」的条目从索引里摘掉，回复里带 `skippedIndex[]`，
   页面 toast 说一句「索引里的 X 还没发布，这次没跟着推」。所以自动那条路安全了。
2. **「发布」只发这一个扩展**（`publishExtensions({name})` → `name/` + `index.json`）。
   以前是整份工作区，抽屉里点一次发布能把你刚造出来还在试的副本一起推上 GitHub
   （`319fd58`，已用 `748dcf5` 清掉）。现在别处未发布的东西不会再跟着走，
   但**同一个扩展目录里**你不想发的半成品仍然会跟着发 —— 那个目录就是发布单位。

## 未同步：点开看，勾哪个提交哪个

顶栏那个 chip（`待提交` / `N 个提交没推`）**点它是看，不是推**。早先点一下直接
`git add` 整个工作区 + commit + push —— 一次点击能把正在改的半截代码推上 GitHub，
而这一页其它地方全都在讲「保存 ≠ 发布」。现在它只开弹窗。

弹窗（`#pending`）的几条规矩，改之前先读：

- **单元是扩展，不是文件。** 一行一个扩展 + 状态药丸（`已发布` / `未发布`）+ `+n −m`；
  点「N 个文件」才展开到文件级。人想的是「把 123 发出去」，不是「提交 index.js」。
  分三段：未发布的扩展（首次进仓库）/ 已发布的扩展 / 类别与仓库文件。
- **代码默认不勾，勾了要过语法闸。** 后端对选中的 `.js` 逐个 `node --check`，不过就整批
  400 并指出文件。机器管语法，人管 diff（每个文件「看 diff」就地展开，`buildDiff` 现成）。
- **本地删除的文件不参与提交，也不能勾。** 那是装卸的私事：`syncExtendRepo` 的删除防火墙
  （`syncExtendRepo` 里 `includeDeleted`）就是为这个存在的，弹窗里给它们划掉、写「本地已删，不提交」。
- **`README` 这类 `other` 单元默认不勾。** 那是误触最近的一格。
- **提交 ≠ 生效。** 提交成功后按钮行换成「重装（让改动生效）」——要不要生效由人说，
  别在提交之后偷偷 reload。
- **失败不关窗。** push 失败（网络 / 凭据 / `repo.lock`）时弹窗留着，错误就地写在底部、
  按钮变「重试推送」，而且**勾选清空、`repush` 置真** ——下次点只推送，不重复提交。
- **「已提交没推」单独一段**在改动列表上面：点一下展开那条 commit 改了哪些文件
  （`/pending/commit?hash=`）。「没提交」和「提交了没推」是两个欠账，别混成一个数字。

## 代码抽屉：读 / 保存 / 发布

商品卡上的「代码 ›」现在在**详情**里（卡上换成 `⋯` 菜单），打开右边一整格：左栏文件，右边 `textarea`。文件列表由 qrd3wh 扫
`<EXTEND>/<name>/` 得到（只列 `.js` / `.mjs` / `.json` / `.md`，跳过点开头的和
`node_modules`，单文件上限 512 KB）。

**保存和发布是两个动作，不许合成一个按钮。**

| 动作 | 打哪条路 | 干什么 |
|---|---|---|
| 保存 | `PUT /v1/extensions/file` | 立刻落盘。**不 commit**。语法不合格当场 400，文件不动 |
| 发布 | `POST /v1/extensions/publish` | 校验 → 重扫 `index.json` → commit → push |

理由不是洁癖：敲到一半的半截文件被推上去，下一轮热重载就会去 import 一个语法错误的模块；
而 `qrd3wh/server.js` 顶上那两行是**顶层 await import**，坏代码留在 master 上，**下一次进程启动
直接起不来** —— 不是这一块坏，是整个会话引擎起不来。

三道闸，缺一不可：

1. **写盘时**：`.js` / `.mjs` 拷成临时 `.mjs` 跑 `node --check`（只解析、不执行）；
   `.json` 先 `JSON.parse`；`nous.json` 额外跑 `index.mjs`，不认就**原样写回**（目录名 == 扩展名、
   字段齐全、`file` 真在，只有它能认）。
2. **发布时**：工作区里每个改过的 `.js` 再过一遍 `--check`，然后 `index.mjs`；任何一步失败就
   **不提交**，把 `node --check` 的报错原样贴到抽屉底部（临时路径已换回仓库路径）。
3. **类别那条 8 秒 debounce 干脆不碰代码。** `POST /v1/extensions/sync` 只 `git add`
   `categories.json` / `index.json` / `*/nous.json`；代码只能走 `publish`。
   （否则「保存了但没发布」的文件会被下一次点标签顺手推上去 —— 保存和发布分开了，
   推的却是同一个工作区，等于白分。）

**并发保护靠 `etag`。** 读文件返回内容哈希；保存时带上 `base`，服务端发现磁盘上的版本变了就
**409**，不把别人的字盖掉。抽屉里显示「未保存 / 已保存 · 待发布 N / 已同步」三态 ——
「没保存」和「保存了没发布」坏起来长得不一样，不能混成一个绿点。

**顺手改的是顶栏的同步 chip。** 保存之后立刻重问 `/v1/extensions/sync`：仓库脏了就不是
「已同步」。页面在本地改了、远端没动的时候显示绿点，是最坏的那种假象。

## 发布 = 发布并生效（别再等 30 秒）

`POST /v1/extensions/publish` 在 commit + push 之后**顺手调一次 `reloadExtensionsNow()`**，
把结果塞进同一个响应的 `reload` 字段（`{ok, head, pullError, load}`）。

之前的写法是「发布 → 页头挂 ⚠ 不一致 → 最多 30 秒后轮询才装进去」：说真话，但每改一行代码
都要吃一次半分钟的税，而且页面上没有任何按钮能立刻催它。现在发布完抽屉里直接写
「已重装，进程里跑的就是这一版」；重装失败就红着写「代码已进仓库，但重装失败」——
仓库成功 ≠ 进程生效，这两件事永远分开说。

两次 `serializeExtendWrite` 是**顺序 await**，不是嵌套：排队链不是可重入的，嵌套会死锁。

## 清单对账：`sections` 不能只信 JSON

卡片上「提示词 N 段」数的是 `nous.json` 的 `sections` —— 那份是手写的。代码里把
`section("cwd", …)` 改成 `section("cwd2", …)` 而忘了回头改清单，页面就会照抄一个谎：
写着 2 段、进程里装的是另外 2 段。

真值在进程里：`GET /v1/extensions` 多回一个 `live`（`{扩展名: [真装上的 section 键]}`，
来自 `registry.snapshot().sections()`）。对不上就：
- 卡片上一条琥珀边的对账行：「清单写 2 段、实际装 2 段 —— 代码里没有「cwd」；代码里多了「cwd2」」
- 顶栏一档「N 个扩展清单对不上」

只对「装上了」的扩展比：装载失败那一档已经在卡片上报了，`live` 里没有它的真值可比。

## 变体：一张卡，多个可装载名字

进程里「变体」只有一种形态：**另一个注册名**。`nous` 之外还有 `nous@review`。会话的
`AgentState.extensions` 存的是字符串数组，名字就是契约 —— 所以变体不是分支、不是版本号，是名字。

- 卡片按**本体**分组（`nous.json` 的 `name`），变体是**详情里**的一行，不另开卡。
- 分隔符用 `@`，**别用 `:`** —— `skill:` 是运行时空白名牌的前缀，`skillNamesOf` 会误伤。
- 变体不改扩展的代码：同一个工厂多递一个 `{ variant, ...params }`，装之前把 `name` 换成
  `名@变体`。扩展自己不用知道 `@` 的存在。
- 变体挂了不连坐本体：本体照跑，那一行标红。

**面板上只有一个入口：新建分支树。** 早先还有一格「登记已有目录」（代码已经在盘上，面板只记路径），
删了：它是「指错目录」那一整排 400/409 的唯一来源，而覆盖的场景（另一份 clone / 非 git 副本）单人用不上；
想接着用某条已有分支，「分支名」改一改就行（已存在会 checkout）。后端 `bind` 动作保留着，
哪天真有一份代码在别处，加个按钮就能放回来 —— 但别把它默认摆在人面前。

代码从哪儿来，两类，语义完全不同：

| | 写在哪 | 跟着仓库走？ | 参与清单对账？ |
|---|---|---|---|
| 参数变体 | `nous.json` 的 `variants` | 是（别人 pull 得到） | 是（`live` 里有 `名@变体`） |
| 目录 / 分支变体 | `data/extensions.local.json` | **否**（本机路径） | 否（代码不在这棵树里） |

把 `/opt/...` 写进 `nous.json` 等于提交上 GitHub —— 所以目录绑定只进本机清单。

### 三个坑

1. **`index.json` 是生成物**：改完 `nous.json` 加一个变体，不重扫就还是旧清单。
   `reloadExtensionsNow` 现在重装前先跑一次 `index.mjs`（扫不动就按旧清单装 —— 能跑比整齐重要）。
   扫完**不 commit**：清单变了就该顶栏显示「待同步」，那才是实话。
2. **新分支树里没有未发布的扩展**：分支从 HEAD 起，而它连 commit 都还没有。建树时把工作区
   那份拷过去，**并且就地提一笔**（`extend: 变体 x 起点`）—— 拷进去的东西在那边是 untracked，
   而 `git worktree remove` 见到 untracked 就拒绝，不提交的话连拆都拆不掉。
3. **拆树 = 这个变体我不要了**：树、本地分支、**GitHub 上那条分支**一起删（`prune` 里做，
   `refs/remotes/origin/<分支>` 在才发 `push --delete`；远端已经被别人删掉不算失败）。
   唯一会拦的情况：`main..分支` 还有提交（空壳 / 已合并的不拦），那时**先手输分支名确认**，
   文案写清「有 N 个提交没并进 main，删了只能从 reflog 里捞」。绝不碰 main（403）。
   - 树里还有没提交的代码 → 409，把 git 的原话贴出来。那是人写的，不是垃圾。
   - 顺序坑：确认框（`#danger`）要从变体弹层里开，**必须先 `closeVariant()`**，否则两层叠着、
     确认按钮被上层的 form 吞掉，点不动（实测踩过）。

参数变体只改清单：要加 / 删就在「代码 ›」抽屉里改那段 JSON 再发布 —— 面板不给它第二个编辑面
（同「不做元数据表单」那条：两个编辑面必然漂移）。

### 抽屉认变体（本机变体才有「另一棵树」）

点变体行 → 「改代码 ›」，抽屉打开的是**那棵树**的文件，标题写 `123@123123`（不写清楚就会改错地方）：

- 读 / 写：`/v1/extensions/files|file?...&variant=` 按变体目录解析根；
- 差异基线：`git -C <那棵树> show HEAD:<相对那棵树根>` —— 拿主树 HEAD 当基线会显示成整篇重写；
- 发布：`publish` 带 `{name, variant}` → 在**那棵树上** `add -A` + commit + `push -u origin <分支>`。
  主树一个字节不动，推坏了也只坏那条分支。toast 会说「已推到 分支 ext/…」。
- 变体自己那份 `nous.json` 优先（分支可以改自己的 `file` / `entry` / `needs`），但 `name` 必须
  还是本体 —— 名字是会话里的契约。
- 参数变体没有「另一棵树」，所以它的「改代码 ›」按本体走。

## 差异视图：编辑槽 + 行级/词级对比

抽屉有两个视图，共用同一份 diff（`public/diff.js`，行级对齐与词级碎片用 vendored 的
jsdiff 8 算，`public/vendor/diff/` —— 这页没有打包器，所以是逐文件拷进来的 ESM）：

| 视图 | 看什么 |
|---|---|
| **编辑**（默认） | 左侧行号槽：绿条=新增、琥珀条=修改、红色 `▾n`=这里删了 n 行；右侧 10px 概览条是改动在文件里的位置，点哪儿跳哪儿；顶栏 `+N −M` 随打字 160ms 防抖更新 |
| **差异** | 与 `HEAD` 的整页对比：双行号（旧/新）、修改行拆成「旧行 + 新行」两行、行内词级高亮、未变区域超过 7 行自动折叠（可点开） |

几个刻意定的点：

1. **比 `HEAD`，不比 `origin`。** 发布推的是工作区 → 本地 commit；origin 落后是另一件事，顶栏在说。
2. **没进 HEAD 的文件**（未发布的新扩展）`base` 是 `null`：整份内容都算新增，提示会说明没有基线。
3. **打字时重算但不重排 DOM**：编辑视图只更新槽和概览条；差异视图是只读的，切过去才重画。
4. **大文件降级**：两侧合计超过 4000 行就不算词级，只做行级（`coarse`），界面上会写一句。
5. **发布成功后自动重读当前文件**刷新 `base`，否则 diff 还在跟旧 HEAD 比。
6. 行高必须两侧一致（`line-height: 20px`）：textarea 和行号槽靠 `scrollTop` 同步，差 1px 就会越滚越偏。

快捷键：`Alt+D` 切视图、`Alt+↑/↓` 上/下一处改动、`Ctrl/⌘+S` 保存、`Esc` 差异态先回编辑态。

## 新建扩展

按一下「＋ 新建扩展」，**只问三样**：名字、一句话说明、类别（可空 = 未分类，写个不存在的名字就顺手建了）。
其余全用默认值：`version 0.1.0` / `file index.js` / `entry default` / `sections []` / `needs {}`。

六条规矩，每条对应一个已经踩过或一定会踩的坑：

1. **名字就是 API。** 会话的 `AgentState.extensions` 里存的是名字，改它等于让所有老会话找不到自己。
   所以这个名字在输入框下面当场标死「建完就改不了」，校验也贴着输入框实时跑（规则 / 撞核心 /
   撞已有目录 / 撞 `.archive` 里的旧账），不靠服务端 409 回来才告诉人。
2. **只给空壳，不给能跑的例子。** 骨架就一句 `export default ({ defineExtension }) => defineExtension({ name })`
   —— 合法的 `Extension` 只有 `name` 必填，所以它装载不会红，但也什么都不做。剩下的用法写在注释里
   （加 section / 加 tool / `needs` 只要那五个键：`api` `defineExtension` `section` `dir` `registry`）。
   新扩展默默往提示词里塞一段内容是最恶心的惊喜，不干。
3. **半截不能留。** 先建 `.new-<name>-<ts>/`（**点开头，`index.mjs` 天然跳过**），两个文件写完、
   `node --check` 过了，才 `rename` 成正式目录；任何一步翻车整棵删掉。生成器不认骨架，也整棵删掉。
4. **建完不提交。** 新扩展的第一个正确状态是「未发布」（untracked）：页面立刻出琥珀卡，chip 报
   `N 个扩展未发布`。发布是用户的事，不是新建的副作用。
5. **建完立刻装。** 建完顺手 `/reload`（新扩展默认算「这台装着」），抽屉自动开在 `nous.json` 上。
   装不上不算建失败：红卡 + 错误行 + 重试就摆在卡片上。
6. **不建重名的归档户。** `.archive/<name>` 还在时拒绝新建，提示去「已归档」里恢复 —— 否则恢复时两边撞车。

顺着第 4 条还有个反向的坑：**未发布的扩展不能「归档」**。它从来没进过仓库，归档它等于
「先把半成品推上去，再归档」—— 真的发生过一次（`.archive/zz-arch` 被推上 GitHub，又 force 回去）。
现在 `archiveExtension` 先看 `isTrackedDir`：没进过 HEAD 的直接 `rm -rf`，不产生提交、不推送，
卡片上那个按钮也改成「删掉」，确认文案跟着变（没有历史可找）。

## 开个会话开发它

抽屉底部「开个会话开发它」：`POST /v1/sessions`（模型取 `/v1/device`）→ 把仓库路径、
`AGENTS.md`、`nous.json`、`index.js` 写进第一条消息（要求**先给方案、别先动代码**）→
`POST /v1/selection` 指向它 → 新标签页打开 qrd3wh。

理由：467 行的 `skills/index.js` 在 `textarea` 里改是自虐，而同一台机器上的会话引擎能读能写能
跑 git。**这一页不打算做成浏览器 IDE** —— 大改交给会话，小改（summary、一行逻辑）留给抽屉。

## 本地删除 / 安装回来（不碰仓库）

`POST /v1/extensions/uninstall {name}` → qrd3wh 把 `<EXTEND>/<name>/` 整个搬进自己的
`data/extend-trash/<name>-<时间>/`，在 `data/extensions.local.json` 记一笔，然后从
`registry` 撤装。`POST /v1/extensions/install {name}` 反向：优先从垃圾站搬回，没有就
`git checkout HEAD -- <name>`。仓库、HEAD、origin 一个字节都不动。

几个不显然但必须守的点：

1. **「这台不装谁」的真值是 `extensions.local.json`，不是「目录在不在」。** 别人一 push、
   `git pull` 一跑，文件可能自己回来；没有这份名单，删掉的扩展会悄悄复活。
2. **状态放 qrd3wh 的 `data/`，不放块根目录**：宿主的 watcher 跳过 `data/`，写它不会把
   进程重启；也不在 Nous-extend 工作区里，不会脏到 git。
3. **`publish` 过滤掉所有 `D`。** 删 tracked 文件必然让工作区留下 ` D`，而发布推的是整个
   工作区 —— 不过滤的话，删了 demo、隔天改一行代码点发布，删除就跟着上 GitHub 了。
   顶栏因此一直显示「本地已删 N 个扩展」，那是实话，不是 bug。
4. **生成物别指向不存在的文件**。`runIndexGenerator()` 跑完 `index.mjs` 后，只把 HEAD 里
   **真有这个目录**的幽灵补回 `index.json`；未发布的新扩展不补。灰卡数据本来就从本机名单来。
5. **`core = nous / skills` 不许删**：`server.js` 顶层 `await import` 就是这两行，删了下次冷启动
   整个块起不来。按钮 disabled，title 写清原因。
6. `git pull --ff-only` 撞上本地删除会失败 —— 错误从 `repo.pullError` 上页面（拉取失败），
   不然热重载停摆了只有日志知道。

**改扩展名**：故意不做，理由见下面那一节。新建扩展已经做了，见上面「新建扩展」。

## 装载状态：别让页面报假平安

`GET /v1/extensions` 的 `load` 字段是**装载结果的唯一真相**：
`{ [name]: { state: "ok"|"failed", error, at, version } }`，外加一个 `__reload__` 表示核心扩展的重装结果。

为什么要它：`syncExtraExtensions()` 装扩展是**每个扩展单独 try/catch** —— 失败只打日志、
**不卸旧版本**（旧代码还能用）。于是“代码坏了”在进程层几乎无感，而页面会继续显示绿卡、
版本号还是 `index.json` 里的新版本。那就是假平安。所以：

1. 失败时 `registry` 不撤、`load` 标 `failed`、错误截到 400 字一行。
2. 卡片实线红边 + 「装载失败」+ 卡上错误摘要（不塞 tooltip：手机没有 hover）+ 「重试装载」。
3. `POST /v1/extensions/reload` = 立刻 `pull` + 重装核心 + `syncExtraExtensions`，
   串进 `serializeExtendWrite`（抢 `index.lock` 会炸），`pinLock` 只在本版变了才写
   —— 写 lock 会触发宿主重启块，不该每次重试都重启。
4. `catalog[].tracked` 来自 `git ls-tree HEAD`：false = 本地有、HEAD 没有 → 未发布琥珀虚线卡。

## 归档 / 恢复 / 彻底删除（会改仓库）

三个动作都是 `POST`，都串进 `serializeExtendWrite`，都 commit + push：

| 动作 | 做什么 | 可逆？ |
|---|---|---|
| `POST /v1/extensions/archive {name}` | `git mv <name> .archive/<name>` → 重扫 → 提交推送 | ✅ 能恢复 |
| `POST /v1/extensions/restore {name}` | `git mv .archive/<name> <name>` → 重扫 → 提交推送 | ✅ |
| `POST /v1/extensions/purge {name}` | `git rm -r .archive/<name>` → 提交推送 | ❌ 只能靠 git 历史 |

前端两个破坏性按钮都要**手输扩展名**才亮；恢复不要确认。

几个跟本地删除不同、必须记住的点：

1. **`.archive/` 是仓库内目录**（不是 `data/`）：备份跟着 `origin` 走，clone 下来也在。
   点开头，所以 `index.mjs` 天然不扫它。
2. **`syncExtendRepo` 默认过滤删除，只有这三个动作传 `includeDeleted: true`**。
   否则 `git rm` 暂存的删除会被过滤成“无事可做”，归档变成假动作。
3. **`git add` 不能 add 已删路径**（`pathspec did not match any files`）。
   `syncExtendRepo` 只 add 仍存在的文件，再用 `git diff --cached` 判断“真有待提交的东西” ——
   纯删除（`git rm`）没有可 add 的文件，但必须提交。
4. **`git mv` 到 `.archive/` 后、commit 落地前**，HEAD 里还挂着这个目录。
   `runIndexGenerator()` 补幽灵时得先查 `.archive/<name>` 在不在，否则会写出一份
   “清单说它在、目录已归档”的矛盾账。
5. **彻底删除会写两次**：第一次失败（断网 / 冲突）时文件已删、删除留在暂存区，
   再点一次要能**收尾那半截**而不是报 404 —— 所以 purge 允许“目录不在但有暂存删除”这条路。
6. 核心扩展（`nous` / `skills`）三个动作全部 403：引擎启动路径上就是那两行 import。

## 改扩展名：**故意不做**

`name` 就是 API：会话的 `AgentState.extensions` 存的是名字，改名等于让所有老会话找不到自己；
`index.mjs` 强制目录名 == `name`；核心两个扩展在引擎启动路径上是硬编码 import。
真要做是「`git mv` + 词表 + 遍历所有会话迁移引用 + 一条 qrd3wh 源码改动」，收益低、破坏性极强。
抽屉里没有改名按钮，是设计，不是漏了。**抽屉也不建文件、不删文件**：只读写已经存在的文件 ——
新建文件意味着要同时回答「`nous.json` 的 `file` / `entry` 改不改」，那是另一个动作。
卡片上的「删除」删的是**整台机器上的这个扩展**，不是抽屉里的一个文件。

## 左栏的菜单

类别行上的上下文菜单：桌面右键、手机长按 520ms、键盘 `ContextMenu` / `Shift+F10`。三项：

| 条目 | 做什么 |
|---|---|
| 新建子类别 | 左栏新建框预填 `工具/` 并聚焦，接着敲名字就行（内置类别只有这一项）|
| 编辑类别名称 | 这一行原地变输入框，**填的是全路径**；回车落盘，`Esc` 反悔，失焦也提交 |
| 删除类别 | 删整枝；右边带影响范围（`N 个扩展` / `空类别`），确认框写明子类别数 |

栏里只显示末段（缩进已经说明父级），全路径在 `title` 和右键菜单头里。

- 长按挪动超过 10px 就当滚动，取消 —— 滑列表不能蹦菜单。
- 长按松手浏览器会补一个 `click`，这一下必须吞掉：菜单就在手指底下弹出，不吞就是「松手即误触」。
- 菜单夹在视口内；点外面 / `Esc` / 滚动 / 改窗口大小都关。
- 改名时筛选跟着走：正在筛「A/x」时把 A 改成 B，筛选变成「B/x」；筛选的类别被整枝删掉就落回「全部」。
- 输入框必须等整串 facet 挂进文档之后再 `focus()` —— 行还在内存里时聚焦会落空（这是真踩过的坑）。

GET  /v1/extensions/pending           改动按单元分组 + 没推的提交

GET  /v1/extensions/pending/commit?hash= 一条没推的提交改了哪些文件
POST /v1/extensions/sync {paths, message} 只提交勾中的路径（代码过语法闸）

## 不做的事

- **不装别人的扩展。** 只有 `Nous-extend` 清单里登记过的扩展才有「装回本机」按钮，而且那其实
  是「把本机卸载掉的恢复回来」，不是从某个 marketplace 拉新包。
  早先那句「一会话一容器时 registry 归谁」已经有答案了：**常驻 qrd3wh 引擎持有 registry**，
  这一页只是视图；装卸作用在这一台的引擎上，不是每个会话。
- **不读仓库文件来回答「装着什么」。** 仓库里写着什么 ≠ 这一刻装着什么。
- **不碰 pi CLI 的扩展。** 那是另一个世界的东西，见上面的表。
